## Hypothesis and implementation boundary

The previous JFR profile attributes material work to ArrayDeque, numeric helpers
and PC stores after loop dispatch removal. Compile supported comprehension values
to real JVM locals, with guarded primitive arithmetic and explicit state maps for
exact instruction-level continuation. Preserve the existing loopBody implementation
as a measured control. Unsupported programs and values must use explicit fallback;
no fixture-specific source, constants, hashes, input pre-scan or output shortcuts.

The primary projection must execute actual local lowering. Additional independent
filtered/unfiltered, scalar/object and arithmetic comprehension programs must
exercise it. Avoid changes to parser, numeric semantics, CLI and default VM paths.
Canonical stack, source PC, loop binding and partial output must be reconstructed
before any callback/error or deoptimization. No replay of current opcode effects,
previous fields, rows or callbacks. Exact primitive guards, overflow, null/missing,
nested custom containers, bignum subclasses, tracing enabled during callbacks,
reentrancy, owned plan structure, failure/reuse and loader lifetime are acceptance
requirements. Conservative shape rejection is preferable to an unsound fast path.

## Approved bounded design

`JvmLocalLoopCompiler.prepare(bytecode): LocalLoopPlan` and
`VM.executeLocalLoops(plan, env)` add a separate opt-in backend. Scalar status
reports actual entry, primitive work and fallback. Plan reports static local,
primitive, guard and spill-site counts plus generated bytes/class count; these
are not dynamic per-op counters. One loader/class per eligible plan, no cache.

Supported first slice: one <=128-op comprehension, static paths, literal object
keys, scalar/object mapping, optional filter, exact Int/Long ADD/SUB/MUL/NEG and
integer comparisons. Unsupported DIV/mod/dynamic keys/logical/general CFG/calls
fall back before effects. Actual JVM locals retain refs or primitive values with
Int/Long tags. Each guard has a compiler-derived live stack map; failure spills
bottom-to-top above canonical base and resumes ordinary VM at the current opcode.
NEXT and append keep canonical loop state. Unknown/custom nested values deopt
before access. Every emitted lookup remains ordered, including access-order maps.
Capacity checks may choose ordinary execution early but must not throw an error
before the canonical instruction. JVM integer semantics span Long; any narrower
fast-path magnitude guard is only an eligibility restriction, not a new language
numeric limit. Old loopBody implementation remains a control.
