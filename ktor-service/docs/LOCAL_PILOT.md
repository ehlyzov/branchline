# Reproducible local price-ingest pilot

This bounded pilot runs repository-controlled Branchline transforms behind the existing Ktor HTTP API. It requires JDK 21 and resolves normal build dependencies; local composite dependency mode uses the current checkout without GitHub Packages credentials.

From the repository root:

```sh
cd ktor-service
./gradlew -Pbranchline.useLocal=true test
./gradlew -Pbranchline.useLocal=true run
```

From another terminal, send synthetic data to the default local port:

```sh
curl --fail-with-body http://127.0.0.1:8080/api/v1/price-change \
  -H 'Content-Type: application/json' \
  -d '{"transactionId":"local-001","warehouseId":"11111111-1111-1111-1111-111111111111","skuId":"22222222-2222-2222-2222-222222222222","price":10.55,"effectiveTime":"2026-01-01T10:00:00Z","source":"synthetic-pilot","needAck":true}'
curl --fail-with-body http://127.0.0.1:8080/api/v1/prices
curl --fail-with-body http://127.0.0.1:8080/api/v1/history
curl --fail-with-body http://127.0.0.1:8080/api/v1/outbox/acks
curl --fail-with-body http://127.0.0.1:8080/api/v1/outbox/events
```

Expected on a fresh process: `CREATED`, accepted ack and one update event. Repeat the same transaction ID with a changed price: `DUPLICATE`, accepted ack, no additional event or history entry. A different ID with older effective time is `STALE`, rejected ack, no mutation. Negative price or more than two fractional digits is `VALIDATION_FAILED`; no mutation event is emitted. Use a fresh process to reset in-memory state.

`PricePilotReplayIT` automates seven ordered requests with a fixed supplied host clock: zero-price creation without ack, a one-cent update, stale input, a changed duplicate with a newer time, excess scale, negative price, and an update ordered by transaction ID at equal time. It checks final price `0.02`, transaction `tx-003`, three history entries/events and six acks. Existing route, domain, bridge and generated-contract tests cover further behavior. This is a synthetic local integration gate, not evidence of production operation.

Branchline validates and composes payloads; Kotlin owns duplicate detection, ordering, persistence and outboxes. Clock and event IDs are host-supplied, with event IDs generated by the service. No storage or duplicate-handling result is credited to a transformation engine. Stores are in memory; restarting resets state and outboxes. There is no durable outbox delivery, Kafka/Postgres integration, operational rollout or production rollback in this pilot.

A separate common **integer cents** profile is compared using real Branchline JVM, Dashjoin JVM JSONata 0.9.10 and Kotlin:

```sh
# From the repository root, outside ktor-service:
./gradlew :jsonata-benchmarks:priceIngestComparison
```

See [comparison protocol](../../jsonata-benchmarks/src/jmh/resources/price-ingest/PROTOCOL.md) for the explicit oracle, typed boundary, missing/null handling, error order, version-change fixtures and negative sensitivity command. Its 65 inputs are examples for one problem, not independent authoring tasks; 50 execute each engine's business rules and fifteen check the shared wire adapter (types and decimal preservation through the declared finite numeric boundary). This comparable profile does not replace the service's decimal-string contracts or generated DTOs.

See the [recorded local results](../../development/evidence/branchline-price-pilot.md). Independent integrator adoption, representative replay datasets, two weeks of observation and a separately authorized blind authoring/maintenance experiment remain P2. No performance, user or AI advantage is inferred from passing functional gates.
